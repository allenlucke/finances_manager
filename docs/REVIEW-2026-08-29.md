**How to read the tags.** *[reproduced]* — I ran it and watched it fail. *[verified]* — I read the

## A. Wrong money — the worst class

A plausible-looking wrong number is the failure this project fears most. Each of these produces one.

**A1. The two dedupe keys do not agree, and the code insists they must.** *[verified]*
`csv_reader.py:461` passes `raw_amount` — signed — into `dedupe_key`, while `amount=abs(raw_amount)`
one line above. `TransactionService.dedupeKey` (`:167-171`) hashes the positive magnitude. So a
debit entered by hand and the same debit imported later hash differently and both stay live. On
top of that, Python strips trailing reference numbers (`_TRAILING_REF`, `csv_reader.py:35`) and Java
does not, and for multi-account files Python keys on a hash of the account number while Java keys
on the account id. The Javadoc at `TransactionService.java:158` claiming the two "must agree" is
currently false, and no test compares them.
*Do:* one spec, owned by the API (see G1), plus a golden-vector test that hashes the same tuples in
both languages.

**A2. OFX drops the institution's transaction id from the key.** *[verified]*
`ofx_reader.py:118` calls `dedupe_key(account_ref, occurred, amount, description)` without the
`fitid` it extracted on the line above. `csv_reader.dedupe_key` has a paragraph explaining that
omitting the id "silently lost $2,100" — three identical same-day transfers collapsing into one.
That bug is fixed for CSV and live for OFX, which is the format the docs prefer for reconciliation.
*Do:* pass `external_id`. One line. Add an OFX fixture with two entries identical but for FITID.

**A3. Trailing-reference stripping collapses distinct checks.** *[reviewer]*
`CHECK #1234` and `CHECK #5678` both normalize to `CHECK`; same date and amount → one key → one row.
Only bites formats with no `external_id_column`, which is exactly where the hash is load-bearing.
*Do:* normalize for the merchant/categorization field; hash the raw description for identity.

**A4. Refunds are forced into transfers, so a refund can never credit its category.** *[verified]*
`csv_reader.py:86` puts `Return` and `Adjustment` in `non_expense_types`, which sets
`is_probable_transfer`, which the API turns into `is_transfer=true`, which the CHECK constraint
turns into `category_id IS NULL` — permanently. An $84 grocery refund cannot be booked against
Groceries; the category stays overcharged forever. `test_csv_reader.py:108` pins this as correct.
"Not spending" (a transfer) and "negative spending" (a refund) are two different things wearing one
flag. *Do:* a distinct `is_probable_refund` that keeps the row categorizable as a credit (see G2).

**A5. Bare transfer patterns delete real expenses from the budget.** *[verified]*
`rules.py:36,38,40` — `\bONLINE\s+PAYMENT\b`, `\bE-?PAYMENT\b`, `\bZELLE\b`. Same class as the
AUTOPAY bug the file itself documents removing. `ONLINE PAYMENT TO CITY UTILITIES` → transfer.
`ZELLE PAYMENT TO PLUMBER JOE` → transfer. Because a transfer is uncategorizable by constraint, the
expense is not misfiled, it is removed. The CACU fixture's memo column is literally `ONLINE PAYMENT`.
*Do:* drop `ZELLE`; require co-occurrence with a card token for the other two, as the
`PAYMENT … THANK YOU` rule already does; and consider returning a low-confidence hint rather than a
0.95 suppression, so the review queue decides.

**A6. A mask match can file a new account's rows into an existing one.** *[verified]*
`ImportService.resolveAccount` (`:104-123`) falls back to `findByUserIdAndMask`, guards only on
`size() != 1`, and returns the match even when its `externalId` is already a *different* key.
Checking `…1234` linked to `hashA`; a savings account also ending `1234` arrives as `hashB`: its
rows post to checking. Both balances wrong, reconciliation off, nothing says why.
*Do:* `if (matched.getExternalId() != null && !matched.getExternalId().equals(accountKey)) return empty()` — it then lands in `unlinked`, which is the behaviour already tested for.

**A7. Reconciliation sums from the beginning of time and ignores the opening balance.** *[verified]*
`R__reporting_views.sql:195-216`: `computed_balance` is every transaction ever, with no lower bound.
`opening_balance` is selected and never used; nothing in Java ever sets it. Unless every statement
back to account opening is imported, every reconciliation row shows a large difference — the
feature accusing a correct import of being wrong, on day one. The same correlated subquery is also
written twice. *Do:* `opening_balance + SUM(period rows)`, or null the difference when no prior
statement establishes a baseline; use a LATERAL join. See G3.

**A8. Budget targets ignore cadence, and mid-month targets do not apply.** *[verified]*
`v_spend_vs_target:176` — `remaining = amount − net_amount` for every cadence. A $1,200/year target
against $150 of monthly spend reports "$1,050 remaining." `cadence` is stored, exposed, never used.
And `tg.effective_from <= s.month` compares against the 1st, so a target set on the 15th does not
govern that month at all. *Do:* normalize the target to the reporting period in the view.

**A9. The budget page shows income inverted.** *[verified]*
`budget.ts:85-87` has no `categoryKind` filter (the dashboard does). The view computes
`net_amount = SUM(−signed_amount)`, so a paycheque arrives negative and `remaining = 3000 − (−3000)`.
Under "Spending by month": Spent `−$3,000.00`, Remaining `$6,000.00`. *Do:* filter to expense, or
give income its own forecast-vs-received table.

**A10. The accounts page sums money with floats, in the browser, across entities.** *[verified]*
`accounts.ts:69`: `reduce((sum, a) => sum + Number(a.balance), 0)`. Forbidden by `models.ts`'s own
comment and by DOMAIN.md. It is also a second net worth that can disagree with the API's, and it
silently adds Personal and Feeling Froggy. *Do:* delete it; use the net-worth report's combined row.

**A11. `SUM(cost_basis)` treats "not applicable" as zero.** *[mine, verified]*
`V5:117`. SQL `SUM` skips NULLs; `Holding.costBasis` is documented as null meaning not-applicable.
Ten positions with two unknown bases report the sum of eight as *the* basis, and the gain is
overstated with no marker. *Do:* `CASE WHEN bool_or(cost_basis IS NULL) THEN NULL ELSE SUM(…) END`.

**A12. The import batch is committed APPLIED before its rows are, and a mid-loop failure leaves it
PENDING with no error.** *[verified]*
`ImportService.importStatement` is `@Transactional`; `recorder.complete` at `:227` is `REQUIRES_NEW`
and commits first. If the outer commit then fails, the batch claims N rows that do not exist. And
`recorder.fail` wraps only the parser call — anything thrown from the row loop rolls back silently,
contradicting the recorder's own "even a crash mid-import leaves a record."
*Do:* catch around the whole body; flip to APPLIED in an `afterCommit` synchronization.

**A13. A brokerage balance is the last snapshot, forever.** *[mine, verified]*
`v_account_balance:76` — once a snapshot exists the transaction sum is ignored. Deposit $10k after the
last positions import and net worth does not move. `balance_as_of` is exposed on the account, but
`v_net_worth` sums it with no marker. And two views now disagree about what a balance is:
`v_account_balance` says market value, `v_statement_reconciliation` says transaction sum.
*Do:* add post-snapshot cash movements to the market value, or surface staleness on net worth too.

**A14. Rows are silently dropped by the footer heuristic.** *[reviewer]*
`csv_reader.py:289` skips any row with fewer than half the header's fields. A three-field rent line
in a nine-column export vanishes with an empty `warnings` list. *Do:* count and warn, or detect
prose by "no parseable date" rather than field count.

**A15. The closing-balance heuristic infers file order from two rows.** *[verified]*
`csv_reader.py:341-344` compares first and last dates. Equal dates, unsorted files, and an
unparseable newest row all pick the wrong balance — and this is the reconciliation checkpoint.
*Do:* `max(balances, key=date)`; warn when the max is not at either end.

**A16. Manual entry cannot record two identical transactions on one day.** *[verified]*
Two $6.50 coffees at the same shop: the second is a 409 "Conflicts with existing data." Python solved
this with `external_id`; Java's manual path has no disambiguator and `ux_transaction_dedupe` spans
deleted rows. *Do:* a per-row nonce for `MANUAL` source — a hand-entered row has nothing to be
idempotent against.

**A17. Three malformed inputs turn into a 500 for the whole file.** *[reviewer]*
Short row (`KeyError`), `NaN`/`Infinity` amount (`InvalidOperation`), a field over 128 KB
(`csv.Error`). The row-level handler at `csv_reader.py:295` catches `ValueError` only. One truncated
line kills a 400-row import. *Do:* `.get()`, broaden the catch, reject non-finite decimals.

**A18. Amount parsing is locale-blind and accepts non-money.** *[reviewer]*
`'84,31'` → 8431. `'1E5'`, `'NaN'`, `'1_000'` accepted. `'84.31-'` and `'84.31 CR'` rejected.
`generic` lists `%d/%m/%Y` but strips commas unconditionally, and tries `%m/%d/%Y` first with no
ambiguity warning. *Do:* grouping separator on `CsvFormat`; handle trailing sign; warn on ambiguous
dates.

**A19. A multi-statement OFX shares one dedupe namespace.** *[verified]*
`ofx_reader.py:72-91` maps every statement with the same `account_ref` and takes the summary from
`statements[0]`. With A2, same amount and date across checking and savings → same key → one dropped.
The CSV path already scopes by `account_key`. *Do:* derive it from `acctid`; one summary per statement.

**A20. Five merchant rules can never match; two match far too much.** *[reviewer]*
`\b` after a truncated word (`UNITED AIR\b`, `QT \d\b`, `BP#\b`) never matches a real description.
`\bDELTA\b` catches Delta Dental; `\bTREASURY\b` catches TreasuryDirect purchases as Taxes — an
asset transfer booked as spending at 0.9 confidence, ahead of the transfer patterns.
*Do:* a table-driven test that every rule matches one realistic string and rejects one.

## B. Security

**B1. Lockout fails open on a caller-supplied header.** *[reproduced]*
`LoginAttemptListener.sourceIp()` returns the first segment of `X-Forwarded-For`; `record()` inserts
it with `?::inet`. A non-IP value makes the insert throw inside the synchronous event listener, the
audit row is never written, and `isLocked` counts rows. Observed: five wrong passwords with
`X-Forwarded-For: nope` → five 409s; correct password → 204; `login_attempt` holds one row. The 409
itself is `ApiExceptionHandler` mapping the cast failure to "Conflicts with existing data" — a
baffling thing to see on a login form. This also contradicts `LocalTokenAuthenticationFilter`, which
refuses to read that header for exactly this reason. *Do:* stop reading it (or validate and fall
back), and make the audit write unable to abort authentication. The test is one minute long.

**B2. Passkeys are dead in the deployed stack.** *[reproduced]*
`nginx.conf` proxies `/api/` only. `passkeys.ts` calls `/webauthn/register/options`,
`/webauthn/register`, `/webauthn/authenticate/options`, `/login/webauthn`. Through `:4200` all four
return `405 text/html`. `proxy.conf.json` proxies them for the dev server, which is why it worked
under `make web`. SECURITY.md lists "passkeys enrolled and enforced" as a gate before real data; that
gate cannot be satisfied in the only stack that will run on the homelab. No test exercises it.
*Do:* `location ~ ^/(webauthn|login/webauthn)` → api; a Playwright assertion that the options
endpoint returns JSON.

**B3. A failed passkey assertion logs you out to the passphrase form.** *[verified]*
`auth-interceptor.ts` exempts `/auth/login`, `/auth/me`, `/auth/csrf`, `/setup` — not
`/login/webauthn`. A rejected assertion is a 401, `signedOut()` fires, state flips to `anonymous`,
and the person is asked for the passphrase they already satisfied — the dead end `auth.ts` documents
`passkey-required` as existing to prevent. *Do:* add both WebAuthn paths to `isAuthCall`.

**B4. No session-id rotation at login.** *[verified]*
`AuthController.login` authenticates in a controller and saves the context. `formLogin` would have
installed `ChangeSessionIdAuthenticationStrategy`; nothing here does, and there is no
`sessionManagement` anywhere. A session id fixed before login is valid after it; the CSRF token is
not rotated either. *Do:* `request.changeSessionId()` before `saveContext`; test that the cookie
value changes.

**B5. On the homelab the entire boundary is one compose line, and D-16 requires editing it.** *[verified]*
`127.0.0.1:` on the port publishing is the only thing bounding `LOCAL_API_TOKEN` in Docker, because
`LOCAL_API_TOKEN_LOOPBACK_ONLY` defaults to `false` there. Reaching the box over Tailscale means
publishing elsewhere — at which point a passkey-bypassing, full-control token is reachable by every
tailnet device, and nothing warns. `LOOPBACK_ONLY` is not in `.env.example` at all.
*Do:* `${BIND_ADDR:-127.0.0.1}`; refuse to start when token set + loopback off + bind not loopback;
better, publish only `web` and route MCP through nginx.

**B6. The MCP file tools will read and upload any file on the machine.** *[mine, verified]*
`import_statement('/etc/hosts')` uploads it. `~/Downloads/../../../etc/hosts` too. No root, no
extension check, no size cap, symlinks followed. `find_statement_files` lists any directory while
its docstring calls it "safe" and it is annotated read-only. `env.py` loads the *entire* `.env`
(Postgres password included) into a long-lived process and walks to `/`. The threat is not you; it
is that statement descriptions are merchant-typed text that flows into the model's context, and the
model chooses the path. *Do:* resolve, allowlist `~/Downloads` (+ configured), enforce suffix, cap
bytes, load only the keys needed, stop at the repo root.

**B7. Statement content reaches the log at the shipped default level.** *[verified]*
`application.yml:66-68` sets the package to DEBUG unconditionally; `AiServiceClient` logs rejected
upload bodies at DEBUG "because SECURITY.md keeps descriptions out of INFO." The mitigation and the
config cancel out. `LOG_LEVEL` in `.env` is honoured by `ai` only. *Do:* `${LOG_LEVEL:INFO}`.

**B8. The CSV parser's `raw` carries the full account number over the wire.** *[verified]*
`csv_reader.py:468` copies every column; `fidelity_history` maps `Account Number`. The positions
parser redacts it and tests for that; the CSV parser does not. Java does not persist `raw`, so the
exposure is the internal hop and B7's log — but it is the exact thing SECURITY.md forbids and the
exact bug already fixed once. *Do:* share `_REDACTED_COLUMNS`; duplicate the positions test.

**B9. Internal exception messages are echoed to the client.** *[verified]*
`ApiExceptionHandler.onIllegalState` returns any `IllegalStateException`'s message as a 422;
`ImportController` catches `RuntimeException` and returns `getMessage()`. Two methods up, constraint
names are deliberately hidden. *Do:* a `DomainRuleViolation` for the intentional cases; everything
else a 500 with the cause logged, not returned.

**B10. First-run setup has a check-then-act race that bricks the MCP token.** *[verified]*
Two concurrent POSTs with different emails both see `count() == 0`. `LocalTokenAuthenticationFilter`
refuses when `users.size() != 1`, so the symptom is a 401 that looks like a wrong token.
*Do:* `CREATE UNIQUE INDEX ON app_user ((true))`.

**B11. The AI service parses untrusted files as root, with no auth and no size limit.** *[verified]*
`services/ai/Dockerfile`: no `USER`; `uv:latest` unpinned; `uv.lock` never copied. `app.py` reads
the whole upload with no cap; no route has authentication. It handles more sensitive bytes than the
API and has fewer controls. *Do:* non-root, pinned, `--frozen`, a content-length cap, and either
the API's token/loopback check or `read_only`/`cap_drop` in compose.

**B12. Sessions live 30 days with no idle timeout and no explicit cookie flags.** *[verified]*
`application.yml:24`. D-12 specifies `Secure`/`HttpOnly`/`SameSite`; none is configured. Under
HTTP-on-Tailscale `Secure` would break the cookie, so it may be deliberate — say so in the config.

**B13. Three places break the schema's own tenant rule.** *[verified]*
`categorization` has no `user_id` and single-column FKs (V2's header calls this "expensive to
retrofit once data exists"). `HoldingRepository.findLatestForAccount` filters on account alone and
the controller discards other tenants' rows in Java *[mine]*. `v_spend_vs_target`'s target join and
`ex_target_no_overlap` carry no `user_id`. Safe today by transitivity, not by statement.

## C. Operations — the gap between the docs and the files

**C1. No backup or restore exists.** *[verified]* Zero hits for `pg_dump|restore` outside prose.
The compose volume comment reasons about backing up correctly, for a backup that does not exist.
*Do:* `make backup` (pg_dump → age/gpg → file), `make restore` into a throwaway project asserting

**C2. No restart policy on any service.** A power blip leaves the box down until someone SSHes in.

**C3. nginx has no `client_max_body_size`.** Default 1 MB; the API allows 10 MB. A 2 MB Fidelity

**C4. No `.dockerignore` anywhere; web does `COPY . .`.** 305 MB of macOS `node_modules` merged over
the `npm ci` result; `.gitignore` default-denies `statements/` and `data/` but nothing stops them

**C5. CI has never run, and would not run everything if it did.** *[verified]* Last push 2022. The
workflow omits the MCP tests, Playwright, and any image build — the image-build job is what the
ROADMAP's own "kept serving old code" post-mortem calls for. No timeouts, no concurrency
cancellation, mutable action tags.

**C6. `make test-ai` fails on a fresh clone.** *[reproduced]* `Failed to spawn: pytest`. Dev deps
are an extra; `uv run` does not install extras. `mcp` uses dependency-groups and works. *Do:* align.

**C7. Both container builds discard their lockfiles.** `npm ci || npm install` throws away the
signal that the lock drifted; the AI image never copies `uv.lock` and resolves fresh at build time.

**C8. Floating base tags everywhere; two of three images run as root.**

**C9. `web` has no healthcheck and `depends_on` is unconditioned.** `reset-database.ts` documents
exactly this flake and works around it with a 60-second poll. The fix belongs in compose.

**C10. `make clean` destroys the dev database silently.** Advertised as "remove build output."
There is also no Postgres major-upgrade path, which with C1 makes a version bump a data-loss event.

**C11. `.nvmrc` says 22; CI and Docker say 24.** *[mine]* Three runtimes across three environments.

**C12. The e2e stack inherits the real `LOCAL_API_TOKEN` and is never torn down.** *[mine]*

**C13. Smaller.** `Makefile:28` advertises `/api/v1/status`, which does not exist. The `JAVA_HOME`
fallback gives wrong advice on Linux. No log rotation. `.mcp.json` hardcodes 8080.

## D. Usefulness — what you will hit as a returning user

**D1. Four screens render an empty state for a server failure.** *[verified]* "No accounts yet.
Add one" on a 500. "Nothing in this date range." "Nothing waiting." Telling someone with three years
of statements that they have no accounts is the worst possible failure. *Do:* loading / error /
empty, as three states, once.

**D2. The dashboard shows a confident `$0.00` net worth when the request fails.** `?? 0` turns
"no data" into money. Same class as the Invalid Date bug. Four of five dashboard requests have no
error handler.

**D3. Clearing the "From" date breaks the ledger screen until refresh.** `isoDate(null)` throws
inside the `valueChanges` subscription, which tears it down; `loading` sticks true forever. Typing an
invalid date sends `NaN-NaN-NaN` to the server and shows nothing.

**D4. You cannot correct a target you set this month.** `budget.ts:149` hardcodes the 1st;
`TargetController` 409s unless the new start is strictly later. Typo a target on the 2nd and it
governs the month, and the error names a date you were never shown.

**D5. Screens the API has and the UI does not.** Holdings (M4 is invisible). Deleted transactions
and restore (delete has no confirmation and no undo, despite soft delete being a design point).
Positions import. And `import.html:78` tells you to "rename or change the type on the Accounts
page," which has no edit operation.

**D6. The reconciliation alert names no account and links nowhere.** The one field you need first
is the one omitted.

**D7. A rejected recategorization stays on screen.** The select shows the refused category; the
error branch does not reload.

**D8. Choosing the same file twice does nothing.** The `<input type=file>` is never reset, so no
change event fires. Re-import is an explicitly supported operation.

**D9. Sign-out can silently no-op.** `logout()` has no error path.

**D10. Silent truncation at 200 rows, 100 review items, 40 budget rows.** `Page.totalElements` is
returned and ignored. No account or category filter on the ledger.

**D11. The dashboard freezes at the month boundary.** `computed` over `new Date()` evaluates once.
Nothing in the app refreshes.

**D12. Sign-in loses the page you asked for; `/login` renders under the signed-in toolbar.**

**D13. Auto-created accounts from an import land under `entities()[0]`** — which can be Feeling
Froggy. The other two screens prefer `kind === 'personal'`. DOMAIN.md calls this the mistake that
matters at tax time.

**D14. Brokerage balances show no as-of date.** The API returns `balanceSource`/`balanceAsOf` for
exactly this; `models.ts` drops them.

**D15. The "Number" column is dead** — the API never returns `mask`. Compiles because strict
templates are off.

**D16. Accessibility.** Zero heading elements in the app. Import failure detail lives only in a
tooltip on a non-focusable span. The transfer marker is `aria-hidden` and tooltip-only. Over-budget
renders a *positive* number in `.amount--negative` — colour is the only cue on the one screen where
it is not redundant. No page titles, no live region on navigation.

**D17. A 4 MB icon font for about fifteen icons**, unbudgeted, on a host with no outbound internet.

## E. Architecture and quality

**E1. A `ThreadLocal` is used to return a value from a service.** `ImportService.lastUnlinked` —
set twice, never removed. Stale on a pooled thread; a tenant leak in a two-user world.
`UnlinkedAccount` is already public; return it.

**E2. Dedupe identity is computed in two languages.** See A1–A3, A19. The fix is structural (G1).

**E3. The rules engine has nowhere for tiers 2 and 3 to go.** First-match over two tuples;
`method="rule"` even when nothing matched, so the API cannot tell "escalate" from "unknown";
confidences on no common scale; rules frozen in source although the file says they should grow from
corrections; no `account_type` threaded through although the OFX reader correctly refuses to guess
without it.

**E4. Duplicated parser helpers, already drifting.** Two `account_hash` implementations; two money
parsers with different semantics for `(100.00)` and `--`; three BOM strategies; `detect_format` is
dead. Encoding policy differs between readers (one rejects cp1252, one mangles it).

**E5. MCP response shapes are inconsistent** *[mine]*: raw JSON, a paged envelope, a list-or-error,
a synthesized dict. `_page` mislabels a plain dict as one transaction (`len(dict)` = key count) —
the trap it was written to prevent. `delete_transaction` asserts `reversible: true` without checking
the API agreed. `list_transactions`' docstring says "omit for no lower bound"; the controller
defaults to the current month.

**E6. Web.** `strict` and `strictTemplates` off (D15 is the consequence). Four ad-hoc error
strategies and no 5xx handling. `accountName`/`entityName`/`money` duplicated across components.
No subscription convention (`takeUntilDestroyed` appears nowhere). `computed` over clock reads.
`patchValue` used in the one form whose siblings document it as the bug.

**E7. Domain violations are signalled with `IllegalStateException`.** See B9.

**E8. `ARCHITECTURE.md` describes a system that does not exist.** "REST + JWT" (D-12 chose
sessions); "API stores the raw file" (it deliberately does not); "asks the AI service to categorize
the new rows" (import does not categorize).

**E9. `ParsedTransaction` does not enforce its own contract.** `amount` is "always positive" by
description only — no `gt=0`, no non-finite rejection. The invariant net worth depends on is not
checked at the wire boundary.

**E10. Small inefficiencies.** `GET /accounts/{id}` runs the full balance report and filters in
memory. `recordStatement` loads every statement to answer `exists`. `warnedAbout` grows unbounded
*[mine]*. `_account_from_preamble`'s bare `"Account"` label will mask an account *name* (`king`).

**E11. Positions import reports updated holdings as "duplicates."** *[mine]*

## F. Tests — what is missing

**F1. No tenant-isolation test anywhere.** Every test seeds one user. Nothing asserts user B gets
404 for user A's ids. The whole security model rests on `findByIdAndUserId` and one repository is
already non-compliant. Insert a second user via JDBC and walk every endpoint. This is the test to
write first.

**F2. No cross-language dedupe test.** One golden-vector table hashed by both implementations would
have caught A1, A2 and A3 at once.

**F3. The import HTTP path has no automated test, and e2e never uploads a file.** The app's primary
workflow — upload, unlinked detection, create-and-retry, duplicate reporting — has zero coverage at
any level. `reset-database.ts` depends on the suite never importing.

**F4. `importPositions` has no automated test.** *[mine]* Verified by hand on the scratch stack;
that should have been a test.

**F5. Reconciliation is only tested with complete in-period history.** A7 is invisible to the suite.

**F6. No test for a row-loop failure marking the batch failed** (A12), nor that APPLIED is not
committed on rollback.

**F7. No lockout test with a hostile `X-Forwarded-For`.** One test pins B1.

**F8. No passkey e2e.** Would have caught B2 and B3. Playwright's virtual authenticator makes it
feasible.

**F9. Web:** `Auth`, `authInterceptor`, `signedInGuard` have no spec; six of seven features have
none; `money.spec` cannot test `today()` (no injectable clock); `api.spec` skips `importStatement`,
the one method with a documented trap; no a11y assertions.

**F10. Parsers:** no robustness suite (short/long rows, duplicate headers, header text mid-file, 100k
rows); no "must never be a transfer" list; no "every rule matches something" table.

**F11. No test that the MCP file tools refuse a path outside an allowlist.**

## G. Where I would take it

**G1. Make dedupe identity server-owned.** The API computes the key from the parsed row with one
spec — external id when present, else account id + date + magnitude + raw description — and the
parser stops computing it. Cross-language drift becomes impossible by construction rather than
guarded by a test.

**G2. Split "transfer" from "refund" in the domain.** `is_transfer` means not spending and stays
uncategorizable. A refund is a *categorizable credit*. One flag cannot carry both meanings, and the
CHECK constraint currently makes the wrong one permanent.

**G3. Make the opening balance a first-class concept.** Either a statement seeds the ledger, or each
account gets an explicit opening-balance row. Reconciliation then works from any starting point.
This is the single biggest usefulness unlock for your first real import.

**G4. Make cadence real.** Normalize targets to the reporting period in the view, or expand to
per-month rows. Until then, only monthly targets are correct.

**G5. Web: one pattern, applied once.** A shared loading/error/empty helper (or `httpResource`),
one error strategy in the interceptor including 5xx, `strict` + `strictTemplates` on, a `money`
pipe, an injectable clock. Most of section D falls out of this.

**G6. Rules engine → scored candidates + one arbitration point.** Each tier returns zero-or-more
candidates on a common scale; rules live in a data file that corrections can append to;
`account_type` is threaded through. This is the shape M3 needs.

**G7. Ops, in order:** backup + tested restore; restart policies; `.dockerignore` ×4; nginx
(`/webauthn`, `/login/webauthn`, `client_max_body_size`); CI running all five suites plus an image
build; bind-address discipline for Tailscale; non-root, pinned images.

**G8. Security for deployment:** session rotation; remove `X-Forwarded-For` from the audit path and
make audit writes unable to abort auth; `DomainRuleViolation`; DEBUG off by default; MCP allowlist.

**G9. Holdings:** add post-snapshot cash movements to market value, surface staleness on net worth,
and reconcile brokerage statements against market value rather than transaction sums.

**G10. Decide what the AI service is.** Today it is internal-only by port mapping, root, unpinned,
unauthenticated, and it handles the most sensitive bytes in the system. Either give it the API's
token/loopback check, or lock it down as a sealed worker (`read_only`, `cap_drop`, size caps).

## What to protect

Five things are genuinely right and should not be traded away while fixing the above: the sign
convention with composite tenant FKs; soft delete with a dedupe index that spans deleted rows;
reporting rules living in one set of views; documentation that records *why*, including the
post-mortems; and the browser suite on its own compose project.
